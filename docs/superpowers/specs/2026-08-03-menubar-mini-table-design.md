# 菜单栏迷你表格重设计 — 设计文档

日期:2026-08-03
状态:已确认(brainstorming 三问锁定 + 设计分节评审通过)

## 目标

重设计菜单栏(NSStatusItem)的 compact 显示,解决用户反馈的三问题:**凌乱**(8 数据点+8 标签混排)、**不对齐**(两行块宽不一致)、**看不懂区分**(标签/数值归属不明)。保留全部 8 个数据点(用户明确「全部都要,但排整齐」)。

## 锁定的需求决策

| # | 决策点 | 共识 |
|---|---|---|
| 1 | 信息量 | 8 个数据点全保留:阿里云 5h/7d、Kimi 5h/周、OpenCode 滚/周、本机 CPU/内存 |
| 2 | 布局骨架 | **迷你表格**:列=数据源(固定顺序 ☁→✨→⚡→▣),行=主/次指标。否决分组卡片+分隔线(仍 16 个文本元素)与单行全展开(~300pt 太宽) |
| 3 | 色彩策略 | **风险变色**:平时黑/白自适应明暗,warning 橙 / critical 红。颜色只有一种语义=风险;否决品牌色常驻(4 彩太闹)与保持单色(不够耳目一新) |

## 布局规格

```
 ☁40%  ✨ 0%  ⚡ 3%  ▣12%
  18%    58%     2%    25%
```

- **列**:数据源,固定顺序 ☁阿里云 / ✨Kimi / ⚡OpenCode / ▣本机。图标:cloud.fill / sparkles / bolt.fill / desktopcomputer
- **行**:上行=主窗口(5h/5h/滚/CPU),下行=次窗口(7d/周/周/内存)。无文字标签,位置即语义
- **对齐**:每列固定宽度 = 图标位 10pt + 值域固定 4 字符宽(`100%` 为最宽),值在值域内**右对齐**(个位数与百位数个位对齐);第 2 行缩进一个图标位宽度,8 个数字严格成网格;列间距 7pt;**无分隔线**(20pt 高度里发丝线只添乱)
- **字号**:值 11pt semibold + monospacedDigit(现 10pt);图标 9pt bold、图标位 10pt 宽;行间距沿用 -1。**总高 ≤21pt**(现 compact ≈20pt):若 11pt 两行溢出菜单栏则降 10.5pt
- **总宽** ≈175pt(现 compact ≈212pt),更窄
- **图例可发现性**:statusItem button 加 tooltip,逐 provider 拼全名说明,如「阿里云 5小时 40% · 7天 18% | Kimi 5小时 0% · 周 58% | …」

## 色彩与渲染

- **放弃 `isTemplate`**(模板图只取 alpha,现有阈值变色代码实际无效——菜单栏里永远单色)。改为非模板手动双套渲染:
  - 读 statusItem button 的 `effectiveAppearance` 判明暗:深菜单栏白基底、浅菜单栏黑基底
  - 对 button appearance 变化做 KVO,明暗切换时触发重渲染(数据 30s 刷新也会重渲染,双保险)
- **风险变色**:每个数字独立按 `ThresholdConfig.band(for:)` 变色——safe→基底黑/白,warning→橙 `(0.95,0.55,0.10)`,critical→红 `(0.92,0.23,0.21)`(沿用面板现有色值)。图标恒用基底色,只有数字变色
- 渲染失败回退:保底云朵图标(沿用现有 render() 兜底)

## 数据行为

- 未配置的 provider **整列隐藏**;列顺序固定,已配置列之间对齐不受隐藏影响(列宽恒定)
- nil(出错/未采样)→ 横杠 `—`,横杠不参与变色(基底色)
- 本机开关关闭时 ▣ 列隐藏;开关开但采样未就绪时该格显示 `—`(沿用 SystemMetricsMonitor 既有语义:首 30s CPU 横杠)
- 点击行为、刷新链路、`renderIconSink` 预渲染缓存机制全部不动

## 集成

- 新渲染函数 `miniTableImage(...)` **替换 `compact` scheme 的现有实现**;`MenuBarDisplayScheme` 枚举、设置项、其余 4 个 scheme(cloudPercent/singleLine/iconOnly/systemStats)一律不动,老用户无感升级
- 非模板渲染仅作用于 compact/迷你表格;其他 scheme 保持 `isTemplate=true`(各自独立 render 出口,互不干扰)

## 测试

无 XCTest(CLT only),用 Verify executable 断言纯函数 + 截图人工验收:

- **纯函数**(抽到 Core 或 renderer 内可测):可见列过滤(未配置隐藏、顺序固定)、横杠规则(nil→"—")、8 值各自的 band 映射、tooltip 文案拼接
- **人工验收**:菜单栏截图核对网格对齐、明暗两态基底色、warning/critical 变色(可临时调阈值触发)

## 明确不做(YAGNI)

列顺序自定义、动画、单列点击动作、发丝分隔线、label 开关、品牌色模式——均不做。
